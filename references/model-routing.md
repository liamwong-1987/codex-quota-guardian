# Codex模型调度

## 目的

在制定计划时为每一步推荐合适的模型等级。质量优先，节省来自正确选模和减少返工，不来自机械地选择更便宜的模型。模型卡是建议，不自动切换模型、创建子智能体或下放任务；默认由当前主智能体执行。

## 三个模型的职责

### Sol：总负责人

用于方向和结构不明确、跨模块、高风险或失败代价高的工作：

- 判断真实目标，处理方向、方案和高风险工作；
- 比较方案、确定架构、划定范围和禁止项；
- 处理跨模块修改、关键业务逻辑、安全与数据风险；
- 诊断任务第一次失败的根因；
- 检查实际差异、重跑关键测试并完成最终验收。

如果拆任务、解释任务和复核结果比直接完成更费力，推荐 Sol 完成整项工作。

### Terra：主力执行者

用于方案已经确认，但仍需要理解上下文、在几个相关文件间判断和处理常规异常的工作：

- 根据明确设计实现正常功能；
- 完成相关文件之间的集成；
- 处理有清晰复现条件的常规问题；
- 编写需要理解业务语义的测试和文档；
- 复查一组相关的小任务结果。

Terra 不适合推翻已确认的方案。发现设计冲突时停止执行并把推荐模型改为 Sol，不自动启动新的执行者。

### Luna：快速助手

只用于范围窄、规则明确、容易验证和恢复的小任务：

- 在指定位置搜索、整理或提取信息；
- 按既有样式完成机械性修改；
- 为明确行为补充小型测试；
- 运行指定检查并报告原始结果；
- 修改少量指定文件，且验收命令已经写清。

涉及架构选择、模糊需求、跨模块协调、核心业务逻辑或高风险操作时，不推荐 Luna。

## 计划中的模型卡

每个可执行任务必须附带：

```text
推荐模型：Sol、Terra 或 Luna
当前执行者：当前主智能体
子智能体授权：否；仅用户明确授权后可改
推理强度：low、medium、high、xhigh 或 max
理由：为什么它足以可靠完成
允许范围：能读取和修改什么
禁止范围：绝对不能碰什么
验收：测试命令或检查步骤
升级条件：什么证据出现后才升级
```

模型卡不完整时不得建议切换模型。即使模型卡完整，也只形成建议，不自动调用该模型。

## 推理强度

- 默认使用 `medium`，作为质量与消耗的平衡起点。
- `low` 只用于机械、低风险、答案容易检查的任务。
- `high` 或 `xhigh` 用于复杂诊断、架构权衡和高风险决策，且必须说明为什么普通强度不够。
- `max` 只用于最困难、质量明显优先于速度和消耗的任务，不作为日常默认值。
- 不因模型更便宜就提高推理强度来抵消任务不清；先把任务说清楚。

## 单执行者边界

本 Skill 默认只使用当前主智能体。选择 Sol、Terra 或 Luna、拆分任务、填写模型卡、运行五人团或判断任务可并行，都不构成子智能体授权。只有用户在当前任务中明确要求使用子智能体或并行代理时，才能另行制定委派任务单；未获该授权时按依赖顺序执行。

## 失败升级

第一次失败后立即停止，由当前主智能体检查原始错误、实际改动和测试结果，并更新推荐模型：

1. 任务不清：重写任务卡，保持原模型。
2. 上下文不足：补充最少必要资料，保持原模型。
3. 环境或测试问题：先修复环境，不升级模型。
4. 能力不匹配：推荐等级从 Luna 调整为 Terra，或从 Terra 调整为 Sol；只更新建议，不自动创建新的执行者。
5. 方案本身错误：返回头脑风暴。

修正后最多再试一次。第二次仍失败时停止并重新规划，不继续轮换模型碰运气。

## 可用性与时效

实际可用模型、推理强度、套餐额度和计费规则以用户当前 Codex 环境与 OpenAI 官方说明为准。模型不可用时不得假装已经调用；应说明限制，并选择当前环境中职责最接近的可用模型。涉及当前价格、额度或模型能力的判断，应先核对官方资料，不把历史数字写成永久事实。
