# 项目执行

## 目的

接住已经确认的方案，小步完成、小步检查，保护已有成果；出现问题时快速诊断，不在错误方向上继续堆工作。

## 理解

执行前读取最终目标、确认方案、必须保留、明确不做、验收标准、风险、已有修改和当前进度。已有需求、设计或进度记录时先读取相关部分。执行阶段不得擅自重新设计；现实与设计冲突时保存证据并退回头脑风暴。

持续项目遵循已有项目规范。没有现成规范且确实需要跨对话继续时，维护简洁的需求、架构和进度记录；简单任务不要为了走流程创建文档。

## 规划

每个任务写清：

```text
任务目标：这一步完成什么
输入资料：需要读取什么
允许范围：可以修改什么
禁止范围：哪些内容不能碰
交付结果：完成后提供什么
验收方法：怎样证明已经完成
失败处理：失败后怎样恢复或返回
推荐模型：Sol、Terra 或 Luna
当前执行者：当前主智能体
子智能体授权：否；仅用户明确授权后可改
推理强度：low、medium、high、xhigh 或 max
选择理由：为什么这个模型足够且可靠
升级条件：出现什么证据才升级模型
```

没有验收方法的任务不能执行。任务要小到可以独立验证，但不要把五分钟的小事机械拆成十步。

## 执行

- 按依赖关系顺序推进。
- 默认由当前主智能体按依赖关系顺序执行。任务可拆分或理论上可并行，不等于授权创建子智能体；只有用户明确要求多智能体执行时才另行规划。
- 修改前检查并保护用户已有成果和稳定状态。
- 代码项目优先使用 Git；非代码项目使用版本文件、修订记录或备份。
- 每完成一个任务立即检查，不把问题积累到最后。
- 不擅自扩大范围，不顺手重构或增加功能。

## 验证

主负责人检查真实证据：文件、差异、测试、截图、运行结果、数据输出或权威来源。不能只相信“已经完成”或“测试通过”的摘要。条件允许时重新运行关键验证。

## 失败处理

第一次失败后停止原方式并保存证据，由当前主智能体判断属于任务不清、资料不足、环境问题、能力边界还是设计错误：

- 任务不清：重写任务单，不升级模型。
- 资料不足：只补充完成任务必需的上下文。
- 环境问题：修复或说明环境，不用更强模型掩盖问题。
- 能力不匹配：把推荐模型从 Luna 调整为 Terra，或从 Terra 调整为 Sol；不得自动创建新的执行者。
- 设计错误：返回头脑风暴，不继续补丁式修复。

修正根因后最多再尝试一次。

第二次仍失败时停止执行，由当前主智能体重新规划。不要自动换一个执行者继续叠加补丁。

## 进度与交付

持续项目记录已完成、进行中、下一步、已知问题、已确认决定、验证结果和恢复方法。简单任务不强制创建大量文档。

最终交付说明：实际完成、修改内容、验证方式、验证结果、未验证项、风险和恢复方法。只有可观察、可检查的结果才算完成。
