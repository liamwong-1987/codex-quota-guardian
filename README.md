# Codex 额度守护者

> 先想清楚，再开始做；把额度花在真正影响质量的地方。

---

## 这是什么？解决什么问题？

用 Codex 做项目，最烧钱、最返工的就三件事：

1. **跑偏** —— 一上来就写代码，做一半才发现目标理解错了。
2. **死循环** —— 修一个 Bug 又造一个 Bug，反复试错，额度和时间一起烧。
3. **失忆** —— 跨对话反复解释背景，已经确认的结论被重新讨论。

**额度守护者**是一套防返工工作法：先让 AI 用「五职业评审团」看清全局，再用结构化弹窗确认方案，然后按任务难度推荐合适的模型（Sol / Terra / Luna），最后小步执行、拿真实证据验收。核心就一句：**不换、不重复、不乱试、完成就停。**

---

## 谁适合用？

- 用 **OpenAI Codex** 做项目、写代码、做研究的人
- 常遇到「做一半方向错了」「反复改 Bug 改不完」的人
- 做跨对话、跨阶段的复杂任务，需要交接和追溯的人
- 对额度和时间敏感、希望一次做对的人

---

## 什么场景用？什么场景不用？

| 任务类型 | 典型情形 | 走法 |
|---|---|---|
| 直接完成 | 翻译、错别字、明确的一处小修改、简单问答 | 不启动完整流程，直接做 |
| 完整流程 | 新项目、新功能、结构性变化、重要决策、复杂研究、方向不明确、返工代价高 | 走完整四步 |

**判断原则**：任务越「改不起」（返工贵、影响大），越要走完整流程。任务执行中一旦发现隐藏复杂性，立即升级，不硬做。

---

## 核心工作流（四步）

```
① 判断方向  →  ② 确认方案  →  ③ 推荐模型+保护额度  →  ④ 执行与交付
  (五人评审团)    (结构化弹窗)     (Sol/Terra/Luna)        (小步验证)
```

### ① 判断方向 —— 五职业评审团

当前主智能体模拟五位不同职业的专家，独立判断、交叉质疑、主负责人裁决：

| 角色 | 要回答的问题 |
|---|---|
| 反对派 | 最可能失败在哪？最坏损失是什么？ |
| 追问派 | 目标、证据、前提哪里没说清？ |
| 机会派 | 有没有更省、更聪明的路径？ |
| 普通用户 | 外部用户看得懂、在乎、会用吗？ |
| 执行者 | 最小可行方案是什么？怎么验证？ |

### ② 确认方案 —— 结构化弹窗

把仍需用户决定的事项，用弹窗集中问 3-4 个关键问题。用户未确认前，不写正式代码、不改正式文件、不装依赖。

### ③ 推荐模型 + 保护额度

为每个任务写一张「模型卡」（推荐模型、推理强度、理由、升级条件）。模型卡只是建议，不自动切换模型、不创建子智能体。

### ④ 执行与交付 —— 小步验证

按依赖顺序推进，每完成一步立刻用真实证据验收（文件差异、测试、截图、运行输出），不能只信「完成了」三个字。

---

## 三档模型等级

| 等级 | 角色 | 适合什么 |
|---|---|---|
| **Sol** | 总负责人 | 方向/结构不明确、跨模块、高风险、失败代价高 |
| **Terra** | 主力执行者 | 方案已确认、需理解上下文、处理常规异常 |
| **Luna** | 快速助手 | 范围窄、规则明确、易验证易恢复的小任务 |

推理强度分 `low / medium / high / xhigh / max`，默认 `medium`。

## 怎么用？

### 1. 安装

把整个目录放到 Codex 的 skills 目录：

```
~/.codex/skills/codex-quota-guardian/
```

`agents/openai.yaml` 是 agent 配置，声明了自动触发和默认提示词。

### 2. 触发

在 Codex 里直接描述任务即可。遇到**新项目、新功能、重要修改、复杂研究、战略决策**时自动启动完整流程；简单问答、翻译、错别字不会触发。

### 3. 跟着四步走

描述任务后，Skill 会依次带你走：先五职业评审 → 弹窗确认方案 → 推荐模型 → 执行验收。你只需要在弹窗出现时做关键决定。

## 完整案例假设

**场景**：你想给订单系统加一个「导出 CSV」功能，怕影响现有筛选逻辑。

1. **判断方向**：五职业评审团指出风险点——导出字段范围、权限、筛选条件一致性、大数据量；最小方案是「只导出当前筛选结果」。
2. **确认方案**：弹窗问你几个关键问题（导出哪些字段？要不要权限控制？最大记录数？），你确认后，方案锁定为「导出当前筛选结果，不改筛选逻辑」。
3. **推荐模型**：这是常规功能实现、方案已明确 → 推荐 **Terra**，推理强度 medium。模型卡写清「禁止改筛选逻辑」「验收=下载文件字段正确、筛选一致」。
4. **执行交付**：小步实现导出接口，每步验证；最终交付改动文件、真实下载测试结果、未覆盖边界（如 10 万条导出）和回退方式。

**为什么省额度**：字段、权限、范围在写代码前就定好了，避免写完才发现导错数据或碰坏筛选。

## 常见问答

**Q：每个任务都必须走五职业评审吗？**
不是。只有新项目、新功能、重要修改、复杂研究、重大决策或高返工风险才走完整流程。翻译、错别字、明确的小修改直接做。

**Q：Sol / Terra / Luna 会自动切换模型吗？**
不会。模型卡只是建议，默认由当前主智能体继续执行，不自动切换、不创建子智能体。只有你明确要求时才另行规划。

**Q：能不能为了省额度跳过测试？**
不能。省额度来自减少返工，不是省掉必要验证。环境不允许验证时，必须如实标记「未验证项」。

**Q：五个职业专家是真的五个 AI 吗？**
不是。是当前这一个主智能体在同一个上下文里模拟五种职业视角，不派生子智能体、不另开任务。

**Q：任务执行失败了怎么办？**
第一次失败先诊断根因（任务不清 / 资料不足 / 环境问题 / 能力边界 / 设计错误），修正后最多重试一次；第二次还失败就停止、重新规划，不碰运气。
